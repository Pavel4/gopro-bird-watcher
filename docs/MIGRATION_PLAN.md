## Текущая ситуация и проблемы

- **Камера**: GoPro Hero 13 в режиме USB Webcam
- **Компьютер**: MacBook M5 (macOS)
- **Подключение**: USB-C кабель
- **Расположение**: кормушка на балконе, съёмка через **2 стекла**
  (~1.5м)
- **Проблемы качества** (см. [VIDEO_QUALITY.md](VIDEO_QUALITY.md)):
  - GoPro USB Webcam: сжатие H.264 при ~4-8 Mbps вместо
    нативных 45-60 Mbps (~60% потеря)
  - Широкоугольный объектив + расстояние (~25% потеря)
  - Два стекла (~15% потеря)
- **Проблемы удобства**:
  - USB провод ограничивает мобильность (камера привязана к Mac)
  - Балкон: -10C, неудобно размещать оборудование
  - Съёмка через два стекла снижает качество
  - WiFi модуль GoPro не работает (требует починки)

## Выбранная схема

```
Кормушка (снаружи у окна другой комнаты)
    |
    | [1 стекло]
    |
GoPro Hero 13 (внутри, на присоске/штативе у стекла)
    |
    | USB-C кабель (~0.5-1м)
    |
Raspberry Pi 5 (внутри, на подоконнике)
    |
    | WiFi (домашняя сеть)
    |
MacBook (SSH управление, мониторинг)
```

**Ключевые улучшения**:
- 1 стекло вместо 2 (+15% качества)
- Камера и Pi в тепле (не на балконе)
- Автономная работа Pi 24/7 (Mac не нужен постоянно)
- Управление по SSH с любого устройства

## Исследование: GoPro к Pi — USB vs WiFi

### Способ 1: USB кабель (РЕКОМЕНДУЕТСЯ)

GoPro подключается к Pi через USB-C. На Pi видится как
`/dev/video0` (V4L2 устройство). Проект уже полностью
поддерживает этот режим.

| Параметр            | Значение                       |
|---------------------|--------------------------------|
| Разрешение          | до 1080p (1920x1080)           |
| FPS                 | 30                             |
| Битрейт             | ~4-8 Mbps (H.264)             |
| Задержка            | минимальная (~50-100ms)        |
| Стабильность        | высокая                        |
| Доп. софт           | не нужен                       |
| Поддержка в проекте | полная (INPUT_SOURCE=usb)      |

### Способ 2: WiFi — Preview Stream (OpenGoPro API)

GoPro Hero 13 может стримить превью по WiFi через
OpenGoPro API (UDP на порту 8554, формат MPEG2-TS).

| Параметр            | Значение                       |
|---------------------|--------------------------------|
| Разрешение          | 720p (фиксировано камерой)     |
| FPS                 | ~24-30                         |
| Битрейт             | низкий (превью-качество)       |
| Задержка            | 200-500ms                      |
| Стабильность        | средняя (WiFi зависимость)     |
| Доп. софт           | OpenGoPro Python SDK, BLE      |
| Поддержка в проекте | нет (нужна доработка)          |

**Важно**: разрешение WiFi Preview фиксировано камерой
(Hero 9 = 480p, Hero 11 = 720p, Hero 13 = ~720p) и
**не настраивается** через API.

### Способ 3: WiFi — RTMP Live Stream

GoPro может стримить по RTMP через WiFi на любой
RTMP-сервер (nginx-rtmp, mediamtx и т.д.).

| Параметр            | Значение                       |
|---------------------|--------------------------------|
| Разрешение          | 480p / 720p / 1080p            |
| FPS                 | 24-30                          |
| Битрейт             | ~2-6 Mbps (зависит от WiFi)   |
| Задержка            | 1-5 секунд                     |
| Стабильность        | низкая (WiFi + RTMP буфер)    |
| Доп. софт           | RTMP сервер на Pi              |
| Поддержка в проекте | частичная (есть в compose)     |

**Проблема**: первоначальная настройка требует приложение
GoPro Quik на телефоне для сопряжения (pairing). После
первого сопряжения можно использовать QR-коды для запуска
стрима без Quik, но **первый раз Quik обязателен**.

### Можно ли обойтись без GoPro Quik?

- **Для USB**: Quik **не нужен вообще**. Переключили GoPro
  в режим "GoPro Connect" → подключили USB → работает.
- **Для WiFi Preview (OpenGoPro)**: Quik **не нужен**, но
  нужна BLE (Bluetooth) связь для первичного включения WiFi
  на камере. На Pi это решается через `bleak` (Python BLE
  библиотека) + OpenGoPro SDK.
- **Для WiFi RTMP**: Quik **нужен один раз** для первого
  сопряжения. После этого — QR-коды без Quik.

### Вердикт: USB — однозначно лучше

| Критерий            | USB          | WiFi Preview | WiFi RTMP    |
|---------------------|--------------|--------------|--------------|
| Качество            | **1080p**    | 720p         | до 1080p     |
| Битрейт             | **4-8 Mbps** | низкий       | 2-6 Mbps     |
| Задержка            | **~100ms**   | 200-500ms    | 1-5 сек      |
| Стабильность        | **высокая**  | средняя      | низкая       |
| Сложность настройки | **простая**  | средняя      | высокая      |
| Quik нужен?         | **нет**      | нет          | да (1 раз)   |
| Готовность проекта  | **полная**   | нет          | частичная    |

**WiFi подключение GoPro к Pi не даёт прироста качества** —
наоборот, качество будет хуже (720p вместо 1080p, нестабильный
битрейт). USB — проще, стабильнее, качественнее и уже полностью
поддерживается проектом.

WiFi GoPro имеет смысл только если физически невозможно
протянуть USB кабель между камерой и Pi (например, камера на
улице, а Pi в доме). В нашем случае камера и Pi стоят рядом
на подоконнике — USB идеален.

## Исследование: все рассмотренные варианты

Перед выбором финальной схемы были рассмотрены 5 вариантов:

### 1. GoPro WiFi/RTMP (починить WiFi модуль)

- Качество: 2/5 (WiFi стриминг ниже USB по битрейту)
- Стабильность: 2/5 (зависит от WiFi, обрывы)
- Стоимость: 0 руб
- Батарея GoPro на стриминге: ~1-2 часа

### 2. Raspberry Pi + GoPro USB на балконе

- Качество: 2.5/5 (1 стекло, но мороз влияет)
- Стабильность: 3/5 (мороз -10C, Pi диапазон 0-50C)
- Стоимость: ~$100-130
- Проблема: оборудование не рассчитано на мороз

### 3. Canon EOS 500D

- **НЕ РЕКОМЕНДУЕТСЯ**
- Live View через gphoto2: всего **480x272** (аппаратное
  ограничение камеры 2009 года)
- Нет Clean HDMI (OSD наложения на видео)
- Качество видеопотока значительно хуже GoPro USB (1080p)

### 4. Перевесить кормушку + 1 стекло (ВЫБРАН)

- Качество: 2.5/5 (+15% от текущего)
- Стабильность: 5/5 (всё в тепле)
- Стоимость: 0 руб (кормушка) + ~$125 (Pi)
- Сложность: минимальная

### 5. IP-камера (на будущее)

- Качество: 5/5 (4K, 8-16 Mbps, без стекла)
- Стабильность: 4/5
- Стоимость: ~$80-180 (камера + PoE инжектор)
- Рекомендуемая модель: Reolink RLC-810A (4K/8MP, PoE, RTSP)
- Потребуется добавить INPUT_SOURCE=rtsp в проект
- **Может быть следующим шагом** после обкатки на Pi

## Первоначальная настройка Raspberry Pi

### Вариант A: Headless — БЕЗ монитора (рекомендуется)

Всё настраивается на Mac до первого включения Pi.

**Шаг 1**: Скачать
[Raspberry Pi Imager](https://www.raspberrypi.com/software/)
на Mac

**Шаг 2**: Вставить SD карту в Mac (через картридер)

**Шаг 3**: В Raspberry Pi Imager выбрать:
- Device: Raspberry Pi 5
- OS: **Raspberry Pi OS Lite (64-bit)** — Debian Bookworm
  (без рабочего стола, экономит ресурсы)
- Storage: ваша SD карта

Нажать шестерёнку (Advanced Options):
- **Hostname**: `birdpi`
- **Enable SSH**: да, с паролем
- **Username**: `pi`
- **Password**: надёжный пароль
- **WiFi SSID**: имя домашней WiFi сети
- **WiFi Password**: пароль от WiFi
- **Locale**: Europe/Moscow, клавиатура ru

**ВАЖНО**: выбирайте Debian **Bookworm**, не Trixie —
у Trixie есть проблемы с WiFi.

**Шаг 4**: Записать образ на SD карту

**Шаг 5**: Вставить SD в Pi, подключить питание,
подождать ~1-2 минуты

**Шаг 6**: Подключиться с Mac:
```bash
ssh pi@birdpi.local
```

Если `birdpi.local` не резолвится:
```bash
# Через роутер: посмотреть список подключённых устройств
# Сканирование сети:
ping birdpi.local
# Или через nmap:
brew install nmap
nmap -sn 192.168.1.0/24
```

### Вариант B: С монитором

Для тех, кто хочет визуальный контроль:

1. Те же шаги 1-4, но можно выбрать
   **Raspberry Pi OS (64-bit)** с рабочим столом
2. Подключить к Pi:
   - Micro-HDMI кабель -> монитор/телевизор
   - USB клавиатура
   - USB мышь (для версии с рабочим столом)
   - Питание USB-C
3. При первом запуске пройти мастер настройки
4. Включить SSH если не включили в Imager:
   ```bash
   sudo raspi-config
   # Interface Options -> SSH -> Enable
   ```

**После настройки монитор/клавиатура больше не нужны** —
всё через SSH.

### Рекомендация: Вариант A (headless)

Проще, быстрее, и OS Lite потребляет меньше ресурсов.
Больше CPU/RAM остаётся для обработки видео.

## SSH-подключение с Mac

### Базовое подключение

```bash
# По hostname (mDNS/Bonjour — работает на Mac из коробки)
ssh pi@birdpi.local

# По IP-адресу
ssh pi@192.168.1.XXX
```

### Настройка SSH-ключей (подключение без пароля)

```bash
# На Mac: генерация ключа (если ещё нет)
ssh-keygen -t ed25519 -C "mac-to-pi"

# Копирование ключа на Pi
ssh-copy-id pi@birdpi.local

# Теперь подключение без ввода пароля:
ssh pi@birdpi.local
```

### Удобный SSH config

Добавить в `~/.ssh/config` на Mac:

```
Host birdpi
    HostName birdpi.local
    User pi
    IdentityFile ~/.ssh/id_ed25519
```

Подключение одной командой:
```bash
ssh birdpi
```

### Полезные SSH-операции

```bash
# Копирование файлов Mac -> Pi
scp file.txt birdpi:~/

# Деплой проекта (скрипт уже есть)
./scripts/deploy-to-pi.sh pi@birdpi.local

# Логи в реальном времени
ssh birdpi \
  "tail -f ~/gopro-bird-watcher/logs/motion_detector.log"

# Перезапуск детектора
ssh birdpi \
  "cd ~/gopro-bird-watcher && \
   docker-compose -f docker-compose.pi.yml restart"

# Статус контейнеров
ssh birdpi "docker ps"
```

### Статический IP (рекомендуется)

Чтобы IP Pi не менялся после перезагрузки:

**Вариант 1** (проще): зарезервировать IP в роутере
(DHCP reservation)

**Вариант 2** (на Pi):
```bash
# Для WiFi:
sudo nmcli con mod "YOUR_WIFI_SSID" \
  ipv4.addresses 192.168.1.50/24 \
  ipv4.gateway 192.168.1.1 \
  ipv4.dns "8.8.8.8,8.8.4.4" \
  ipv4.method manual
sudo reboot
```

## Pi к домашней сети: WiFi vs Ethernet

### Raspberry Pi 5 имеет оба модуля встроенных:
- **WiFi**: Dual-band 802.11ac (2.4 GHz + 5 GHz),
  до ~217 Mbps рядом с роутером
- **Ethernet**: Gigabit (1000 Mbps), стабильные ~940 Mbps

### Сетевая нагрузка проекта — минимальная

Видео с GoPro приходит по USB напрямую в Pi и
обрабатывается локально. Сеть используется только для:
- SSH управление: ~0.01 Mbps
- Telegram отправка видео: ~2-5 MB эпизодически
- Обновление кода (git pull / rsync): редко

### WiFi — рекомендуется

- Нет лишних проводов до роутера
- Pi нужен только провод питания + USB к камере
- Даже при обрыве WiFi — Pi продолжает запись локально,
  видео отправит в Telegram когда связь восстановится

### Ethernet — если WiFi нестабилен

- Нужен только если Pi стоит далеко от роутера
  (3+ стен, слабый сигнал)
- Стабильнее, но требует прокладки кабеля

### Вердикт: WiFi

WiFi **не влияет на качество видео** — GoPro подключена
к Pi по USB напрямую. Сеть нужна только для управления
и отправки готовых видео.

## Максимальное качество GoPro через 1 стекло

### Физические улучшения

- **Камера вплотную к стеклу** — минимум отражений
- **Чистое стекло** с обеих сторон
- **CPL фильтр** на GoPro (~$15-25) — убирает блики
- **Тёмная ткань** вокруг камеры — убирает отражения
  комнаты в стекле
- **Узкий FOV** на GoPro — крупнее птицы в кадре

### Программные улучшения (уже в проекте)

- **ROI + Crop**: детектировать движение в области
  кормушки, записывать обрезанное видео с увеличением
- **Качественное кодирование**: CRF 17, preset slow

### Что НЕ поможет

- Увеличение разрешения — GoPro USB всегда отдаёт
  сжатый H.264 при 4-8 Mbps
- USB 3.0 vs 2.0 — битрейт ограничен камерой
- WiFi вместо USB — качество только ухудшится
